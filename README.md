# Скрипт оператора — прототип

Инструмент для подбора клиники и врача под услугу (колоноскопия, гастроскопия,
МРТ/КТ, профгигиена) с готовым текстом сообщения для пациента.

Полный план проекта — в [PLAN.md](PLAN.md).

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Открывать по адресу **http://localhost:5173/**

Сервер привязан к `127.0.0.1` явно (`server.host` в `vite.config.js`):
на этой машине `localhost` резолвится сначала в IPv6-адрес `::1`, который
не отвечает. Браузер откатывается на IPv4 сам, так что обычно всё работает,
но если страница вдруг не открывается — попробуйте `http://127.0.0.1:5173/`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | Сборка статики в `dist/` |
| `npm test` | Тесты ядра — граф метро, скоринг, линтер, целостность данных |
| `npm run seed` | Пересоздать демо-данные. Импортированный каталог не трогает — для этого `npm run seed -- --force` |
| `npm run geodata` | Пересобрать координаты станций и справочник районов/улиц |
| `npm run rendercheck` | Проверка, что интерфейс рендерится без ошибок |
| `npm run ratings` | Обновить рейтинги клиник с Яндекс.Карт |

Даты слотов в демо-данных считаются от дня генерации. Если прототип полежит
неделю и «ближайшее окно» уедет в прошлое — просто выполните `npm run seed`.

## Как устроен экран

1. **Услуга** — кнопки сверху или клавиши `1`–`5`.
2. **Что именно** — частотные подвиды кнопками, остальное поиском с синонимами
   («поясница» найдёт пояснично-крестцовый отдел).
3. **Где пациенту удобно** — одно поле на всё: **адрес, метро, район или улица**.
   Оператор не выбирает тип, просто печатает то, что назвал пациент.

   Метро, районы и улицы ищутся мгновенно по локальному справочнику.
   Конкретный дом ищется в геокодере — см. раздел «Поиск адреса» ниже.
4. **Карта** — точки клиник с ценой прямо на метке. Синий кружок — где удобно пациенту. Клик по точке подсвечивает
   карточку справа, двойной клик открывает её.
5. **Список справа** — карточки с тегами: доступность записи, локация, стаж
   специалистов, количество врачей, качество сервиса, оборудование.
6. **Провалиться внутрь** — кнопка «Подробнее». Открывается окно почти во
   весь экран. Список остаётся на месте, окно закрывается по Esc, клику мимо
   или «Закрыть».

### Как устроено окно клиники

Сверху — название, адрес, метро и расстояние. Под ними полоса, которая никуда
не уезжает: средняя стоимость кейса, длительность и теги. Справа, тоже всегда
на виду, — готовый текст для пациента.

Остальное разложено по вкладкам: **Врачи**, **Фото клиники**, **Ответы
клиники**. Прокручивается только содержимое вкладки.

Так сделано потому, что одной лентой всё это давало три тысячи пикселей
прокрутки, а оператору за раз нужно что-то одно: либо выбрать врача, либо
найти ответ на вопрос пациента. Цена и текст сообщения нужны всегда — они
из вкладок вынесены.

### Фотографии клиники

Вкладка «Фото клиники» — крупный кадр, подпись и лента превью снизу.
Пациент почти всегда спрашивает «а что там вообще», и оператору проще
посмотреть самому, чем пересказывать анкету.

Фото в анкетах не приезжают, их собирают сотрудники. Поэтому файлы лежат в
`public/clinics/<клиника>/`, а список — в `data/overrides.json`:

```json
"clinicPhotos": {
  "cl-ооо-скандинавский-центр-здоровья": [
    { "url": "/clinics/skandinavsky/entrance.webp", "caption": "Вход в клинику" }
  ]
}
```

Порядок в файле — порядок показа. Импорт `overrides.json` не трогает, так что
переимпорт анкет фотографии не потеряет. У клиники без фотографий блока просто
нет — заглушку не рисуем.

### Ответы клиники на анкету

Вкладка «Ответы клиники» — лист «Общие вопросы» из анкеты: седация и наркоз,
подготовка, гистология, стоимость, оборудование, ограничения. Разделы идут
блоками сверху вниз и всегда раскрыты — оператор читает это пациенту вслух,
раскрывать и искать по ходу разговора некогда.

Анкета одна на клинику и покрывает обе процедуры, поэтому раздел чужой
процедуры отсекается: при колоноскопии не показывается «ТОЛЬКО ЭГДС»
(40 вопросов из 49), при гастроскопии — «ТОЛЬКО КОЛОНОСКОПИЯ» (34 из 49).
Отсечение по разделу, не по отдельному вопросу: в «Стоимости» остаются оба
пакета, там их всего два.

Вопросы, на которые клиника не ответила, так и подписаны — «клиника не
ответила». Придумывать за клинику нельзя.

### Аргументы — про ту процедуру, за которой пришли

У эндоскописта в анкете тезисы сразу про обе процедуры: «выполняет более 2000
гастроскопий в год» и «более 500 колоноскопий в год». В сообщение идут только
те, что про выбранную услугу, плюс нейтральные — стаж, категория, отношение
к тревожным пациентам. Пациенту, который пришёл за колоноскопией, число
гастроскопий не говорит ничего.

На экране оператора у врача видны оба показателя: там это полезно, он держит
в голове всю картину. Отсекается только то, что уходит пациенту.

Что считать «чужой процедурой», записано в одном месте — `src/core/service.js`.
Оттуда же это правило берёт вкладка «Ответы клиники», которая прячет раздел
анкеты по другой процедуре.

### Цены в сообщении нет

В тексте для пациента суммы не бывает ни в одной тональности. Средняя
стоимость кейса — внутренний показатель по юрлицу, а не цена услуги: назвав
её, мы пообещали бы сумму, которую пациент на месте не увидит. Настоящих цен
по услугам в анкетах пока нет, а придумывать их нельзя.

Стоимость оператор называет отдельно, когда узнает её у клиники. В карточке
клиники средняя стоимость кейса по-прежнему видна — она для оператора,
не для пересылки.

Это закреплено тестом: в сгенерированном тексте не должно быть ни суммы,
ни плейсхолдера цены.

### Админка: кнопка «Сохранить»

Админка живёт по адресу `http://localhost:5173/#admin`. Кнопка **«Сохранить»**
пишет правки прямо в `data/overrides.json` — тот самый файл, который читает
основной экран. Vite видит запись и перезагружает страницу, так что правка
появляется сразу, без ручного перекладывания файлов.

Работает это **только при `npm run dev`**: запись делает маленький плагин
дев-сервера (`vite.config.js`), на собранной статике писать некуда. Там
админка скажет об этом и предложит «Скачать файл» — старый путь никуда
не делся, он остался как запасной.

Плагин пишет ровно один файл и принимает только объект с известными
разделами: эндпоинт открыт всем, кто дотянулся до дев-сервера, и превращать
его в «запиши что угодно куда угодно» нельзя. Комментарий в начале файла
сохраняется. Черновик по-прежнему лежит в `localStorage`, так что закрытая
вкладка не стоит часа работы.

Импорт анкет `overrides.json` не трогает — правки сотрудников переживают
любой повторный `npm run import`.

### Незаполненное поле — это минус, а не середина

В скоринге пустая цена и пустое окно считаются худшим значением, а не
нейтральной серединой.

Раньше там стояло 0,5 — «не награждаем и не наказываем». На деле это была
награда: клиника без цены получала полбалла, а самая дорогая из клиник
с заполненной ценой — ноль. Из-за этого клиника в 6 км без единой цифры
обходила клинику в 3,8 км с заполненной ценой, и порядок в списке выглядел
случайным.

Пустое поле — это не «средне», это «нам нечего сказать пациенту». Такая
клиника не должна выигрывать у той, про которую всё известно.

Стоит помнить, что сейчас у всех клиник приоритет A, а ближайшее окно
не заведено ни у одной. Значит, вес приоритета (0,35) и вес окна (0,2)
на порядок не влияют вовсе — выдачу решают расстояние и цена. Как только
появятся B и C и настоящие слоты, картина изменится.

### Фильтр «ВИП-пациент»

В «Уточнениях», сразу под вопросом о седации, стоит галочка «ВИП-пациент?».
Включена — в выдаче остаются только
клиники, отмеченные как подходящие для такого пациента; выключена — на подбор
не влияет вообще.

Отметка ставится **руками**, в админке: `#admin` → Клиники → «Подходит
ВИП-пациенту». Вывести её из данных нельзя: ВИП — это про сервис, палаты,
отношение и договорённости отдела, а не про цифру в анкете клиники. Придумать
за отдел, кого не стыдно предложить, мы не вправе, поэтому сами ничего
не помечаем.

Пока не отмечена ни одна клиника, фильтр даёт пустой список — и в этом случае
на месте выдачи написано именно это, а не «ничего не подошло»: пустой экран
из-за незаполненной отметки и пустой экран из-за жёстких условий подбора —
разные вещи, и оператор должен их различать.

### Рейтинг с Яндекс.Карт

Рейтинг стоит рядом с названием филиала в шапке окна: «★ 4,9 · 1564 отзыва
на Яндекс.Картах · сегодня». Плашка — ссылка на карточку организации, а дата
показывает, когда мы смотрели. Старше трёх дней — становится оранжевой: это
чужое число, снятое в известный день, и оператор должен видеть, не протухло
ли оно, прежде чем называть его пациенту.

В списке клиник рейтинг показан коротко, под ценой: «★ 4,9 · 1564». Ссылки
там нет — карточка кликабельная целиком, и переход на Яндекс перебивал бы
выбор клиники; дата всплывает подсказкой, а показывается прямо в строке
только когда устарела.

**В сообщении пациенту** рейтинг идёт отдельной строкой сразу под клиникой:
`★ 4,9 на Яндекс.Картах — 1564 отзыва`. Звезда читается в любом мессенджере
и отбивает строку лучше, чем слово «рейтинг». Ничего не приукрашиваем: число
и источник, пациент откроет Карты и увидит то же самое.

Если рейтинга нет — строки нет, лишней пустой строки в тексте не остаётся.
Если он снят больше 30 дней назад — в текст не попадает вовсе: за месяц число
успевает измениться, а пациент проверит. Оператор в этом случае видит под
сообщением подсказку, что рейтинг устарел и надо выполнить `npm run ratings`.

**Откуда берётся.** Официального способа нет: API поиска по организациям
отдаёт адрес, телефоны и часы, но не рейтинг — Яндекс не открывает отзывы
сторонним сервисам. Поэтому `npm run ratings` запрашивает обычную страницу
организации и читает то, что Яндекс сам пишет в `og:description`. Это не API:
разметка может поменяться в любой день. Скрипт на этот случай не подставляет
выдуманное число — он говорит, что не разобралось, и оставляет прежнее
значение с прежней датой.

Стоит знать: условия использования Яндекс.Карт (п. 4.6) разрешают данные
только для личного некоммерческого использования и запрещают копирование без
письменного разрешения. Внутренний рабочий инструмент под это не подпадает.
Технически рисков немного — несколько запросов в сутки, по одному раз в четыре
секунды, — но если Яндекс начнёт показывать капчу, скрипт остановится сам
и скажет об этом.

**Награда «Хорошее место».** Её Яндекс присуждает по оценкам пользователей
и пишет в том же описании страницы: «🏆 Обладатель награды «Хорошее место —
2026»». Скрипт забирает её вместе с рейтингом и годом — «Хорошее место» без
года ничего не говорит, прошлогодняя награда и сегодняшняя не одно и то же.
В карточке она стоит плашкой рядом с рейтингом, в списке — трофеем после
числа отзывов. Нет награды — нет и плашки, ничего не подставляем.

**Ссылки на клиники** вставляют сотрудники в админке: `#admin` → Клиники →
«Карточка на Яндекс.Картах». Ссылка должна вести на нужный филиал — у сетей
карточка на каждый адрес своя, и рейтинг у них разный.

**Раз в сутки.** Результат ложится в `public/ratings.json`, приложение читает
его на лету — пересобирать и передеплоивать ради числа не нужно, достаточно
обновить файл. Задание в планировщике Windows (путь подставьте свой):

```bash
schtasks /create /tn "Скрипт: рейтинги" /tr "cmd /c cd /d C:\Users\Admin\Desktop\skript && npm run ratings" /sc daily /st 06:00
```

Когда сервис переедет на хостинг, то же самое ставится в cron рядом со
статикой.

Если скрипт решат не использовать, рейтинг можно вписывать руками прямо
в `public/ratings.json` — приложение не знает, откуда взялось число.

### Расстояние — по прямой, и так и написано

Над списком клиник написано «Считаем от: …», а в карточках — «N м / N км».
Это расстояние **по прямой** от выбранной точки, и подпись об этом есть везде,
где показано число.

Время в пути мы не показываем и не пишем в сообщении: пока пациент не назвал
точный адрес, мы не знаем, где он находится, а называть срок наугад — врать.
Это покрыто тестами: в тексте для пациента не должно появляться ни «от вас»,
ни «минут в пути».

## Поиск адреса

Метро, районы и улицы лежат локально и ищутся мгновенно. Конкретный дом
локально не найти, поэтому адрес ищется в **геокодере Nominatim**
(OpenStreetMap): бесплатно, без ключа.

Запросы уходят только по явному вводу оператора, не чаще одного в секунду,
ограничены рамками выбранного города и кэшируются на время сессии.
Дубли одного дома (здание, подъезды, входы) схлопываются в одну строку.

**Про «навсегда бесплатно»:** это чужой публичный сервис.
[Его правила](https://operations.osmfoundation.org/policies/nominatim/)
разрешают нечастые запросы от людей и запрещают массовые. Несколько операторов,
вводящих адрес руками, укладываются с большим запасом, но гарантий сервис
не даёт — как и с тайлами.

Для полной независимости геокодер поднимается локально: официальный
[docker-образ Nominatim](https://github.com/mediagis/nominatim-docker) плюс
выгрузка OSM по нужным регионам. Тогда, как и со своим `.pmtiles`, никакой
внешней зависимости не остаётся. В коде для этого достаточно поменять адрес
эндпоинта в `src/core/geocode.js`.

Если геокодер недоступен, поле продолжает работать по метро, районам и улицам —
в подсказках появится сообщение об этом.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `1`–`5` | Выбрать услугу |
| `/` | Фокус в поле «где пациенту удобно» |
| `Enter` | Открыть выбранную клинику, а внутри — скопировать текст |
| `Esc` | Вернуться из клиники к списку |
| `↑` `↓` `Enter` | Навигация в подсказках поиска |

## Что попробовать

1. **Колоноскопия от Автозаводской** — точки на карте, клик по точке, «Подробнее».
2. **Введите «академическ»** — в подсказках сразу и станция, и район. Выберите
   район: время в пути пересчитается с учётом пешей части до метро.
3. **Введите «Профсоюзная 15»** — найдётся конкретный дом. Строка «Считаем от»
   сменится на «адреса пациента», предупреждение исчезнет, а в сообщении
   появится «Дорога от вас».
3. **МРТ → напечатайте «поясница»** — поиск по синонимам. Для МРТ продаётся
   аппарат, а не врач: карточка и шаблон сообщения другие.
4. **Галочка «Клаустрофобия»** — на карте останутся только открытые томографы,
   остальные уйдут в «Отсеяно клиник» с причиной.
5. **Вкладка «Противопоказания»** — отметьте кардиостимулятор: появится красная
   плашка, записывать нельзя.
6. **Впишите в текст «мы гарантируем результат»** — линтер подсветит нарушение
   ФЗ-38 ст. 24.
7. **Медцентр на Курской** (в диагностической колоноскопии) — у врача нет
   подтверждённых данных, и в сообщении о нём только имя, без регалий.
8. **Переключите город на Санкт-Петербург** — свой метро-граф, свои районы и клиники.

## Структура

```
data/
  metro.json      станции с координатами и перегонами (Москва + СПб)
  places.json     районы и крупные улицы для поиска
  catalog.json    клиники, врачи, услуги, цены — ДЕМО, генерируется seed.js
  content.json    шаблоны сообщений, возражения, подготовка, противопоказания

  seed.js         генератор демо-каталога; здесь же видна структура таблиц
```

## Импорт из рабочего Excel

```bash
npm run import -- "СКРИПТ_ОПЕРАТОРЫ.xlsx" "Анкета клиники.xlsx" --name "ООО «КЛИНИКА БУДЬ ЗДОРОВ»"
```

Файлов можно передать сколько угодно: общий со списками маршрутизации
и отдельные анкеты клиник. Читает их как есть и раскладывает по таблицам сервиса.

**Импорт перезаписывает `data/catalog.json` целиком**, поэтому передавайте
за раз все файлы, которые должны попасть в сервис. Вернуть демо-данные —
`npm run seed`.

### Две раскладки анкеты

Клиники присылают анкету по-разному, импортёр понимает оба варианта:

- **всё на одном листе** — имя листа считается названием клиники;
- **три листа** «Филиалы / Общие вопросы / Врачи» — названия клиники в файле
  нет, его нужно передать через `--name`. Сколько таких анкет, столько
  и `--name`, в том же порядке. Результат:
`data/imported.json` (каталог) и `data/imported-details.json` (анкеты клиник
и юрлица, по которым анкет ещё нет).

Лист «Общие вопросы» попадает в каталог как `clinicQa` — плоский список
`{ clinicId, category, question, answer, sort }`. Его показывает окно клиники.

**Фото врача.** В столбец «фото» клиники часто вписывают ссылку на страницу
врача на своём сайте, а не на картинку. Такой адрес в `<img>` даёт битую
иконку, поэтому импорт берёт только ссылки на файлы
(`.jpg/.jpeg/.png/.webp/.gif/.avif`), остальные отправляет в предупреждения.
Без фото рисуются инициалы на градиенте — и то же самое, если ссылка протухла.

Скрипт ничего не выдумывает: чего в файле нет, то попадает в отчёт
«чего не хватает для работы».

### Что понимает

| В файле | Куда попадает |
|---|---|
| Листы `Скрипт_<услуга>_<город>`, блок **МАРШРУТИЗИРУЕМ** | клиники, приоритет A |
| Юрлицо из списка | `legalName`; пациенту показывается название без «ООО» и без капса |
| Тот же лист, блок **УВОДИМ** | `isAvoided` — такие клиники не показываются никогда |
| Столбец «Ср. стоимость кейса» | `avgCaseCost` по городу и услуге |
| Лист-анкета клиники, шапка филиала | адрес, метро, какие услуги делают, есть ли седация |
| Блок «Категория — Вопрос — Ответ» | седация, оборудование, ограничение по весу, длительность, отказы |
| Таблица врачей | врачи, стаж, категория, образование, фото, тезисы |
| «Что делает особенно хорошо», «ЭГДС/колоноскопий в год» | тезисы для сообщения пациенту |
| «Рекомендуете тревожному пациенту» | врач по умолчанию при тональности «тревожный» |

Все данные из анкеты помечаются `confidence: confirmed` — они пришли от самой
клиники, значит их можно называть пациенту.

### Что импортёр делает сам

- **Геокодирует адреса** через Nominatim и кэширует в `data/geocode-cache.json`,
  чтобы повторный импорт не ходил в сеть. Адреса приводятся к понятному виду:
  «ул. 2 ая Кабельная дом 2 , строение 37» → «2-я Кабельная улица, 2».
  Если дом не нашёлся, координаты берутся по улице — с предупреждением.
- **Сопоставляет юрлицо анкеты со списками маршрутизации**, в том числе когда
  Excel обрезал имя листа до 31 символа.
- **Привязывает клинику к станции метро** по названию из шапки, понимая
  и «ЮВАО, м. Авиамоторная», и «ст. метро "Московские ворота"/Московский р-н».
  Если такой станции нет в справочнике — привязывает к ближайшей по координатам,
  с предупреждением.
- **Не создаёт услуги во сне там, где седации нет.** Если в анкете «Седация
  доступна — нет», варианты с седацией не заводятся вовсе.
- **Не пускает в тезисы нули и «нет».** «0 колоноскопий в год» достижением
  не считается.
- **Раскладывает врачей по услугам** из колонки «Что выполняет»: врач, который
  делает только ЭГДС, в подборе колоноскопии не появится.

### Чего в файле нет — и без чего сервис не заработает

Импортёр это перечисляет после каждого запуска:

- **цена по конкретной услуге** — в файле только средняя стоимость кейса
  по юрлицу. В сообщение пациенту цена не идёт вовсе (см. ниже), но оператору
  нужно знать стоимость гастроскопии и колоноскопии отдельно, с седацией и без;
- **ближайшее свободное окно** — без него нельзя обещать сроки, а это один
  из главных аргументов;
- **минуты пешком от метро до входа** — считаются один раз руками при заведении
  филиала;
- **телефон и часы работы филиала**.

Ещё одно ограничение: `data/metro.json` — демонстрационное подмножество
(113 станций). Реальные адреса клиник в него часто не попадают: например,
Авиамоторной там нет. Для боевой работы нужен полный справочник метро
двух городов.

## Данные

`data/catalog.json` — плоские таблицы, один к одному с листами будущей
Google-таблицы: `clinics`, `clinicMetro`, `clinicServices`, `doctors`,
`doctorServices`, `doctorSellingPoints`, `services`, `serviceVariants`.

Реальные данные просто заменяют этот файл — код приложения не меняется.
Структуру полей смотрите в `scripts/seed.js`, там она задана явно и с комментариями.

Важные соглашения:

- `priorityTier` — `A` / `B` / `C`, ручной приоритет отдела. Даёт 35% веса в скоринге.
- `confidence` у врача и у каждого тезиса — `confirmed` (подтверждено клиникой,
  можно называть пациенту) или `unverified` (только для глаз оператора).
  **В сообщение попадают только `confirmed`.**
- `ratingValue` — внутренний сигнал сортировки. В текст пациенту не выносится.
- `slotUpdatedAt` старше недели → карточка получает штраф и пометку «данные старые».

## Карта: MapLibre, бесплатно и без ключей

Карта на **MapLibre GL**. Ключи не нужны ни в одном из режимов — подложка
выбирается в `src/core/basemap.js`:

**Режим 1 — тайлы OpenStreetMap.** Работает сразу, ничего настраивать не надо.
Это режим по умолчанию. Годится, чтобы попробовать и показать коллегам.

**Режим 2 — свой файл `.pmtiles`.** Рекомендуемый для боевой работы.
Вся подложка лежит одним статичным файлом рядом с приложением: ничей сервис
не задействован, нельзя ни превысить лимит, ни лишиться доступа, ни столкнуться
с изменением условий. Работает и без интернета.

### Почему для постоянной работы нужен режим 2

Тайлы `tile.openstreetmap.org` бесплатны, но это чужой сервер.
[Правила OSMF](https://operations.osmfoundation.org/policies/tiles/) прямо
предупреждают: коммерческим сервисам доступ может быть закрыт в любой момент,
никаких гарантий и SLA нет. Для внутреннего инструмента, от которого зависит
работа отдела, это риск.

Свой `.pmtiles` этот риск снимает полностью и навсегда: данные OpenStreetMap
под лицензией ODbL, платить некому и не за что, нужно только сохранить
копирайт на карте (он отображается автоматически).

### Как сделать свой файл .pmtiles

1. Скачайте `pmtiles` CLI — [релизы на GitHub](https://github.com/protomaps/go-pmtiles/releases).
2. Вырежьте нужный кусок из планетарной сборки. Скачивать всю планету не нужно:
   CLI забирает только выбранную область через Range-запросы.

```bash
pmtiles extract https://build.protomaps.com/20250101.pmtiles moscow-spb.pmtiles --bbox=29.5,55.4,38.3,60.2 --maxzoom=14
```

3. Положите файл в `public/` и укажите путь в `.env.local`:

```
VITE_BASEMAP_PMTILES=/moscow-spb.pmtiles
```

4. Перезапустите `npm run dev`.

Для Москвы и Петербурга на `--maxzoom=14` файл выходит небольшим — десятки
мегабайт. Каждый следующий уровень зума примерно удваивает размер.
Обновлять достаточно раз в несколько месяцев: карта города меняется медленно.

Сервер должен отдавать файл с поддержкой Range-запросов — обычная статика
это умеет.

### Почему не Яндекс.Карты и не 2ГИС

**Яндекс.** [Условия бесплатного использования](https://yandex.ru/dev/commercial/doc/ru/)
требуют, чтобы проект был публично доступен — не во внутренней сети, не за
регистрацией, — и запрещают коммерческое использование и «мониторинг и
диспетчеризацию». Внутренний инструмент отдела не подходит по всем трём пунктам,
а лицензия стоит [195 000 ₽ в год](https://yandex.ru/maps-api/tariffs).

**2ГИС.** Библиотека бесплатна, но демо-ключ действует месяц, дальше подписка.
Для «навсегда бесплатно» не подходит.

### Про координаты

Координаты станций, районов и улиц в демо **приблизительные** и заданы руками
в `scripts/geodata.js`. Клиники расставлены на нужном удалении от своей станции.
В боевой версии координаты клиник приходят из геокодера или от самой клиники.

### Известная тонкость

MapLibre принимает координаты в порядке **`[долгота, широта]`** — наоборот
относительно наших данных, где везде `[широта, долгота]`. В `MapView.jsx`
конвертация сделана явно в каждом месте; при правках это легко забыть.

Клики по меткам ловятся делегированием на контейнере по атрибуту `data-clinic`,
а не событиями самой карты — так обработчик не зависит от конкретной
картографии, и её можно поменять, не трогая логику.
